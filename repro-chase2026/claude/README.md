# Reproduction — CHASE 2026, text-based LLM track

Spec-driven reproduction of *Emotion Recognition in Agile Software Meetings:
A Comparative Study of ML, DL, and Text-based LLM Approaches*, modules 01–05 of
`specifications/`. The classical-ML and deep-learning tracks are out of scope
and are not implemented.

Everything generated by this reproduction lives under `claude/`. Nothing outside
this directory is written to; the delivered material under `data/`, `results/`
and `tools/` is read-only input and validation reference.

## Layout

```
claude/
├── repro_common.py            # paths, label set, model/display maps, loaders
│                              #   (loader/normaliser helpers verbatim from
│                              #    tools/compare_per_emotion.py)
├── 01_inference_nocontext.py  # Spec 01 — Ollama, no-context prompt
├── 02_inference_context.py    # Spec 02 — Ollama, 15-utterance context window
├── 03_evaluation_metrics.py   # Spec 03 — llm_models_metrics.csv + 5 ranking CSVs
├── 04_per_emotion_analysis.py # Spec 04 — per-emotion CSVs + context-effect report
├── 05_latex_tables.py         # Spec 05 — results/LLMs/*_rows.tex
├── run_all.py                 # runs 03 → 04 → 05, writes run_manifest.json
├── requirements.txt           # pinned per Spec 00 §3
├── .venv/                     # Python 3.10.20 with the pinned versions
└── results/                   # generated artefacts, mirroring results/
```

`claude/results/` mirrors the `results/` sub-tree named in the specs exactly
(`llm_models_metrics.csv`, `LLMs/llm_results_rows.tex`, …). Pass
`--output-root results` (or set `REPRO_OUTPUT_ROOT`) to any script to write to
the literal spec paths instead.

## Running

Every script is executed from the repository root.

```bash
claude/.venv/bin/python claude/run_all.py
```

That runs the reproducible core (modules 03 → 04 → 05), validates each artefact
against the committed reference, and writes `claude/results/run_manifest.json`
with the resolved dependency versions.

Individual modules:

```bash
claude/.venv/bin/python claude/03_evaluation_metrics.py
claude/.venv/bin/python claude/04_per_emotion_analysis.py
claude/.venv/bin/python claude/05_latex_tables.py
```

Modules 01–02 need a running Ollama server with all 16 Spec 00 §6 tags already
pulled (they never pull implicitly — a missing tag aborts with the tag name).
They are **not** part of `run_all.py`: Spec 00 §3 states a re-run will not
bit-match the delivered bundles, and modules 03–04 consume the delivered ones.

```bash
claude/.venv/bin/python claude/01_inference_nocontext.py
claude/.venv/bin/python claude/02_inference_context.py
```

## Environment

Python 3.10.20 with the Spec 00 §3 pins, resolved exactly:
`scikit-learn==1.3.2`, `pandas==2.1.4`, `numpy==1.26.4`, plus `ollama` and
`tqdm` for modules 01–02. No other third-party library is imported.

Recreate with:

```bash
uv venv --python 3.10 claude/.venv && uv pip install --python claude/.venv/bin/python -r claude/requirements.txt
```

## Determinism

The evaluation path (03–05) contains no stochastic operation, so **no random
seed is set** — Spec 00 §3 explicitly forbids introducing one. Iteration orders
are fixed and explicit. Two consecutive `run_all.py` runs produce byte-identical
output for all 14 artefacts. Inference (01–02) uses
`options={"temperature": 0}`; no RNG applies there either.

## Deviations from the spec text

Three places where the specification text and the committed reference artefacts
disagree. The committed artefacts are the definition of done (Spec 00 §1), so
they win; each is commented at the call site.

1. **Subset row order in `llm_models_metrics.csv`** — Spec 03 §5 says
   `('full', 'test')` per model; the committed 64-row file emits
   `('test', 'full')`. Reproduced as committed
   (`repro_common.SUBSET_WRITE_ORDER`).

2. **`hallucination_rate` when nothing survives** — Spec 03 §4.2 defines it as
   `hallucinations / total_seen`, guarded only by `total_seen == 0`. The
   committed row `deepseek-r1_8b-nocontext-test` (`total_seen=72`, `samples=0`)
   carries `0.0`, not `1.0`, so the reference generator also zeroes it when
   `samples == 0`. That guard is reproduced; no other row is affected.
   `hallucination_rate_inclusive` is unaffected and still computes to `1.0` for
   that row, as committed.

3. **Float precision in `llm_models_metrics.csv`** — Spec 03 §5 describes "full
   pandas precision"; the committed values are rounded to 6 decimals
   (`10/381 = 0.026246719…` is committed as `0.026247`). Floats are rounded to
   6 decimals before writing.

Two further quirks are reproduced deliberately rather than fixed:

* **`per_emotion_metrics_wide.csv` column naming** is buggy in
  `tools/compare_per_emotion.py` (Spec 04 §1.5) — the flatten re-appends
  `context` to names that already contain it, so the "friendly reorder" list
  never matches and columns land in raw unstacked order. Kept as written.
* **`llm_results_rows.tex` trailing space** — the committed file ends its final
  row with a single trailing space (the per-emotion row files do not). Matched
  so the diff is byte-exact.

Also carried over as committed: the inconsistent Mixtral display names —
`Mixtral-8x (7B)` in `llm_results_rows.tex`, `Mixtral 8x (7B)` in the two
`*_full_rows.tex` files, `Mixtral 8X (7B)` in the two `*_test_rows.tex` files.

## Prompt sources for modules 01–02

The delivered `prompt_*.txt` files and the reference labeler scripts differ in
whitespace: `prompt_no-context.txt` appends the user-message template to the
system prompt (Spec 01 §5.1 says to use the split form), and
`prompt_context.txt` wraps the second paragraph over two lines where
`emotion_labeler_context.py` keeps it on one. The scripts' prompts are used —
they produced the delivered bundles, and Spec 02 names its script authoritative.
Both modules verify the embedded prompt against the `.txt` on disk and print a
note if they diverge, without failing.

`llama3.3:70b` is excluded from `MODEL_LIST` (no results exist for it) and the
duplicated `gemma3:27b` is de-duplicated, per Spec 00 §6.
